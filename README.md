# Prompt2Process

### Turn any SOP into a digital employee.

Every company runs on written rulebooks, called **SOPs** (Standard Operating Procedures). They cover how to pay a vendor's bill, check a loan application, verify a scholarship, pre-audit an insurance claim, process a refund, or onboard a new hire. Today people follow those rulebooks by hand, one document at a time. The work is slow, repetitive and error-prone.

**Prompt2Process reads an SOP and creates an AI agent, a *digital employee*, that does the job.**
- It reads the documents, validates IDs, cross-checks the facts and applies the SOP's rules.
- It decides the outcome and drafts the letter.
- It asks a human only where the SOP says a human must decide.
- It earns autonomy the way a new hire does: by proving its accuracy first.

It's one platform for many sectors. A new department is just a new SOP.

## In plain words
- **The agents are software, not people.** Meera, Kavya, Vidya and the others are AI agents ("digital employees"). Their names are labels you choose when you hire them.
- **We are the platform.** A bank, hospital, college or shop would use Prompt2Process inside its own back office: it sets up its company profile and approvers, then hires digital employees for its departments.
- **The demo company is fictional.** *Amaravati Group (demo)* and all its documents are generated by our seed scripts: invoices (including scanned ones), loan applications, marksheets, hospital bills, product photos and new-joiner files. Real data never ships with the repo.
- **It starts empty.** Nothing is hard-coded: company name, approvers and people come from onboarding. **Load demo workspace** runs the same hiring pipeline with demo data.

## How a digital employee works
1. **Hire.** Pick a template or upload any SOP (`.md`, `.txt` or `.pdf`).
   - Gemma 4 asks about the gaps (who approves, which limits apply).
   - It then **compiles the SOP into a typed workflow plan**.
   - A **checker runs 8 checks** on the plan: structure, unique step IDs, known actions, least privilege, parameters, references and types, conditions, and company policy.
   - Errors go back to Gemma for up to 2 automatic repair rounds. If the model is unavailable, the template's reference plan is used, and it's checked too.
2. **Work.** Each document or case runs through the plan on **LangGraph**.
   - Deterministic steps (parsing, GSTIN/PAN/IFSC/Aadhaar checks, three-way match, rules, decision tables) run as plain code. They're instant, free and auditable.
   - **Gemma 4 is used only where judgement is needed**: reading scanned pages and photos, classifying, and writing letters.
3. **Earn trust.**
   - **Shadow:** runs everything but only simulates side effects.
   - **Backtest:** replays labelled past cases and measures accuracy.
   - **Supervised:** a manager signs off each case's actions.
   - **Autonomous:** acts within the SOP's limits on its own.
4. **Audit.** Every hire, step, approval, correction and plan version is logged.

## Features
| Area | What's in it |
|---|---|
| **Hiring** | Template library or custom SOP; clarifying questions; SOP → plan compiler; 8-check plan checker; automatic repair loop; plan versions with diffs; workflow graph editor |
| **Execution (LangGraph)** | One-node interpreter `StateGraph`; `SqliteSaver` checkpoints (tasks resume after a restart); human approval gates with `interrupt()` / `Command(resume=…)`; retries with backoff; fallbacks |
| **Earned autonomy** | Shadow → Supervised → Autonomous. Promotion needs measured backtest accuracy (≥ 85 % for Supervised, ≥ 90 % plus approved supervised work for Autonomous); each template sets how many labelled cases count as evidence |
| **Backtests** | Replay labelled history in shadow mode: route accuracy, per-issue precision/recall, hours saved |
| **Learning** | Learns expense categories from the company's bookings and from manager corrections (TF-IDF + logistic regression). Confident cases need no AI call |
| **ML** | Amount anomalies (ratio-to-vendor-median rule + Isolation Forest); late-payment risk (logistic regression on payment history) |
| **Safety** | Reversible masking of Indian identifiers (PAN, Aadhaar, GSTIN, IFSC, bank a/c, phone, email) before model calls; prompt-injection screening; documents fenced as untrusted data; file sandbox; money-moving steps must be guarded, and side effects need a condition or an approval (enforced by the checker) |
| **Reliability** | **Chaos mode** injects failures live. **Self-healing**: when a step keeps failing, Gemma explains why, and a bounded patch (more retries or an escalation fallback) is checked and sent for approval |
| **Roles (RBAC)** | Owner, Department manager, Process designer, Reviewer and Auditor, enforced by the API (`X-P2P-Role`) and reflected in the console |
| **Console** | Owner cockpit (hours and ₹ saved, AI calls per case, escalation rate), workforce, work queue with a live step timeline, case view with source documents and field confidence, approval inbox with keyboard shortcuts, hire wizard with a live compile log, audit log with CSV export, settings with the Gemma trace. Dark and light themes |

## Architecture
```
 SOP (.md/.txt/.pdf) ──► Gemma 4: clarify + compile ──► Plan JSON ──► Checker (8 checks) ──► repair ≤ 2
                                                                        │ ok
                                                                        ▼
 Intake (folder · ledger · case folders) ──► Task ──► LangGraph runner (StateGraph + SqliteSaver)
                                                         │  each step = a registered skill
                                                         ├─ deterministic code (parse, validate, match, rules)
                                                         ├─ Gemma 4 (read scans/photos, classify, draft)
                                                         ├─ ML (anomaly, risk, learned classifier)
                                                         └─ interrupt() ──► Inbox (approve / reject) ──► resume
                                                         ▼
                                     Outcome · outputs · audit log · KPIs ──► React console
```
- **Backend:** Python 3.12, FastAPI, LangGraph, SQLite (JSON document store and checkpoints), `backend/app/`
- **Frontend:** React 19, Vite, TypeScript, Tailwind v4, `frontend/src/`
- **API reference:** `API_SPEC.md`, or `/docs` on a running server

## Built on open source
**Upstream project: [LangGraph](https://github.com/langchain-ai/langgraph)** (MIT). Prompt2Process's execution engine is built on it:
- `StateGraph` runs every digital employee's plan step by step.
- `SqliteSaver` checkpoints every task, so work survives restarts and resumes exactly where it paused.
- `interrupt()` and `Command(resume=…)` implement human approval gates. A task pauses, the decision lands in the Inbox, and the graph resumes with it.
- `InMemorySaver` isolates backtest replays from real work.

Also built with: FastAPI, Pydantic, Uvicorn, scikit-learn, NumPy, PyMuPDF, ReportLab, Pillow, rapidfuzz, PyYAML, python-dotenv, google-genai, React, Vite, TypeScript, Tailwind CSS, React Router, TanStack Query, React Flow (`@xyflow/react`), Recharts, lucide-react, sonner, and Fontsource (Inter, JetBrains Mono, Noto Sans Devanagari / Telugu).

## Gemma 4
Gemma 4 runs through the Gemini API (`google-genai`). Each job goes to the model that suits it:

| Job | Model | Thinking |
|---|---|---|
| Routine steps: classify, read cases, draft letters and reminders | `gemma-4-26b-a4b-it` (MoE, ~4B active) | minimal |
| SOP compiler: clarifying questions, plan, repair | `gemma-4-26b-a4b-it` | minimal (configurable) |
| Vision: scanned invoices, product photos | `gemma-4-31b-it` | minimal |

- **Where Gemma is used:**
  - `hire:clarify`, `hire:compile` and `hire:repair`
  - `extract_invoice` (scanned pages, or when the parser is unsure)
  - `extract_case` (low-confidence fields)
  - `classify_expense` (when the learned model isn't confident)
  - `classify_text`, `assess_image`, `draft_message`, `draft_reminder`
  - `healing_explanation`
  - Everything else is deterministic code.
- **Fallbacks:** if Gemma is slow, rate-limited or offline, every call falls back safely (template parser, keyword classifier, letter templates, reference plan), and unclear cases go to a human. The app runs fully offline for development.
- **Robustness:**
  - Token budgets are capped at each model's published output limit.
  - Server-side deadlines are longer for compiler calls.
  - Per-minute quota errors (429) wait as long as Google asks.
  - JSON is extracted even when the model adds prose, with one repair attempt.
- **Backtests skip letter writing**, so evaluation spends calls only on decisions.
- **Seeing the calls:** *Settings → Gemma 4* lists every call (purpose, model, latency). `python -m app.llm.check` (run from `backend/`) tests the key and models, image reading and the SOP compiler, and prints thinking tokens and finish reasons per call.

## Quick start (Windows PowerShell)
Prerequisites: Python 3.12+, Node 22+, and a free Gemini API key from <https://aistudio.google.com/apikey>.

```powershell
git clone <this-repo-url> Prompt2Process
cd Prompt2Process
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
Copy-Item .env.example .env      # then put your GEMINI_API_KEY in .env (never commit it)

cd backend
python -m app.llm.check          # optional: verify Gemma 4 access
uvicorn app.main:app --port 8000
```
In a second terminal:
```powershell
cd frontend
npm install
npm run dev                      # http://localhost:5173 (proxies /api to :8000)
```
Open <http://localhost:5173> and either set up your company or click **Load demo workspace**. Then:
1. Run a backtest per employee.
2. Promote employees to Supervised.
3. In the Work queue, click **Ingest** and then **Run**.
4. Approve items in the Inbox.
5. Hire someone new from an SOP.

To serve the console from the API as one app, run `npm run build` in `frontend/`; the backend then serves `frontend/dist` on port 8000.

macOS / Linux: use `source .venv/bin/activate` and `cp .env.example .env`.

### Configuration (`.env`)
| Variable | Default | Meaning |
|---|---|---|
| `GEMINI_API_KEY` | — | Gemini API key (`GOOGLE_API_KEY` also works). Without it the app runs offline |
| `GEMMA_MODEL` | auto-detect | Model for routine steps (recommended `gemma-4-26b-a4b-it`) |
| `GEMMA_VISION_MODEL` | `GEMMA_MODEL` | Model for images (recommended `gemma-4-31b-it`) |
| `GEMMA_DEEP_MODEL` | `GEMMA_MODEL` | Model for the SOP compiler |
| `GEMMA_THINKING` / `GEMMA_THINKING_DEEP` | `minimal` / model default | Thinking level: `minimal`, `low`, `medium`, `high` or empty |
| `GEMMA_DEEP_MAX_TOKENS` | `16384` | Output budget for compiler calls (capped at the model's limit) |
| `GEMMA_DEEP_TIMEOUT_S` / `LLM_TIMEOUT_S` | `600` / `180` | Server deadline per compiler call / per other call |
| `LLM_MODE` | `auto` | `auto` (live if a key is set), `live` or `offline` |
| `EXTRACTION_MODE` | `template_first` | `template_first` (parser first, Gemma when unsure) or `llm_first` |
| `HOURLY_COST_INR` | `300` | Used for the "cost saved" KPI |
| `P2P_DATA_DIR` / `P2P_STATE_DIR` | `./data` / `./state` | Demo documents / database and checkpoints |

## Deploy (Render)
The repo includes a multi-stage `Dockerfile` (builds the console, then runs the API serving it) and a `render.yaml` Blueprint:
1. On Render, go to **New → Blueprint** and choose this repository.
2. Enter `GEMINI_API_KEY` when asked.
3. Deploy. The health check is `/api/health`.

The free plan's disk is temporary, so the demo workspace may need to be loaded again after a restart.
